STEP 1

Navigating the Site Workspace & File Permissions

Linux HestiaCP Isolated User Environment

When a web domain is created in Hosta, our server provisions an isolated directory tree under your Linux user account. All public web traffic from Nginx and Cloudflare is directed to your website's dedicated directory.

Choose Stack Directory Template: Isolated path: /home/<user>/web/<domain>/
Web Root: public_html/ (Nginx direct static serving) Entry File: public_html/index.html 
/home/<username>/web/<your-domain.com>/
├── public_html/                     # Web root served directly by Nginx
│   ├── index.html                   # Primary entry point (HTML or compiled React/Vue/Vite)
│   ├── favicon.ico                  # Site favicon
│   ├── robots.txt                   # Search crawler directives
│   └── assets/                      # Bundled CSS, JS, images, media
│       ├── index-Df82a.js           # Compiled JavaScript bundle
│       └── style-Aa94c.css          # Compiled stylesheets
├── logs/                            # Nginx access.log and error.log
└── stats/                           # Web visitor analytics (AWStats)

How it works: For plain HTML/CSS/JS or Single Page Apps (React/Vue/Vite), upload files directly into public_html/ with index.html at the root. Nginx automatically handles gzip/brotli compression and browser caching.

Application Directory: public_html/ Daemon Entry: public_html/server.js (PM2) 
/home/<username>/web/<your-domain.com>/
├── public_html/                     # Application folder managed by PM2
│   ├── server.js                    # Node.js backend entry (Express / Nest / Fastify)
│   ├── package.json                 # Project dependencies & npm run scripts
│   ├── package-lock.json            # Deterministic dependency lockfile
│   ├── .env                         # Secrets (PORT=3000, DB_HOST, DB_PASSWORD)
│   ├── node_modules/                # Server-installed dependencies (run: npm install)
│   └── public/                      # Static client assets served by Express static middleware
├── logs/                            # Nginx reverse proxy access & error logs
└── stats/                           # Web bandwidth and visitor metrics

How it works: The Node.js application runs as a persistent background process using PM2 listening on port 3000. Nginx acts as a high-speed reverse proxy routing public HTTPS web requests to your application.

Document Root: public_html/public Front Controller: public_html/public/index.php 
/home/<username>/web/<your-domain.com>/
├── public_html/                     # Laravel Project Root
│   ├── app/                         # Application models, controllers, middleware
│   ├── bootstrap/
│   │   └── cache/                   # [chmod 775] Framework service cache
│   ├── config/                      # Configuration files (app.php, database.php)
│   ├── database/                    # Migrations and seeders
│   ├── public/                      # Web Root (Set Document Root here in Dashboard)
│   │   ├── index.php                # Front controller entry point
│   │   ├── .htaccess                # Apache URL rewrite rules
│   │   └── robots.txt
│   ├── resources/                   # Blade templates, CSS, JS source files
│   ├── routes/                      # web.php, api.php
│   ├── storage/                     # [chmod 775] Logs, uploaded files, session cache
│   │   ├── framework/               # Compiled blade views and sessions
│   │   └── logs/laravel.log         # Laravel runtime exception log
│   ├── .env                         # Secrets (APP_KEY, DB_DATABASE, DB_PASSWORD)
│   ├── artisan                      # Artisan CLI runner (php artisan)
│   ├── composer.json                # PHP package dependencies
│   └── vendor/                      # Composer installed packages (run: composer install)
├── logs/                            # Nginx web server access & error logs
└── stats/                           # Traffic analytics

Security Requirement: In the Control Panel, point Custom Document Root to public_html/public. This protects your .env secret database credentials and source code from public web access!

Required Linux File & Folder Permissions

File System Item Numeric Mode Symbolic Mode Explanation
Web Directories 755 rwxr-xr-x Owner can read/write/execute; public web server can read & traverse.
Standard Files (.html, .js, .css, .php) 644 rw-r--r-- Owner can read/write; web server can read without dangerous execution.
Laravel Storage & Cache 775 rwxrwxr-x Allows PHP-FPM web process to write session, log, and view cache files.
# Fast Terminal One-Liner to Reset Standard Permissions:
find /home/$USER/web/yourdomain.com/public_html -type d -exec chmod 755 {} +
find /home/$USER/web/yourdomain.com/public_html -type f -exec chmod 644 {} +
NOTE: Preventing 403 Forbidden Errors

Never set files to 777. Full world-writable permissions pose an extreme security vulnerability and can trigger automated HestiaCP security blocks. Stick to 755 for folders and 644 for files.

STEP 2

Uploading Site Files (Choose Your Preferred Method)

File Manager • SFTP Client • Terminal CLI
Method A: Dashboard File Manager (Fastest for Single Files & ZIPs)

The web-based File Manager allows you to manage files directly inside your browser without installing third-party software:

  1. Open File Manager: Sign into the Dashboard → navigate to Files or click the folder icon next to your domain.
  2. Browse to Web Root: Double-click web → yourdomain.com → public_html.
  3. Create Local ZIP Archive: On your computer, select all files inside your project or build directory (e.g. index.html, assets/) and compress them into a .zip archive.
  4. Upload Archive: In the File Manager toolbar, click Upload File, select your .zip file, and wait for the progress bar to complete.
  5. Extract In-Place: Right-click the uploaded .zip archive → select Extract Archive. Your files will instantly unpack into public_html.
  6. Delete ZIP File: Right-click and delete the original .zip to recover your account SSD storage quota.
PRO TIP: Zip the Contents, Not the Parent Folder

When creating your ZIP archive, select the contents inside your build folder (e.g., select index.html and assets/) instead of right-clicking the parent folder itself. If you zip the folder, you will end up with an unwanted nested directory like public_html/my-app/index.html!

Method B: SFTP / FileZilla & VS Code (Best for Large Projects)

SFTP (SSH File Transfer Protocol) provides encrypted, rock-solid transfers for larger codebases, full directories, and iterative programming.

Protocol SFTP - SSH File Transfer
Host / Server IP hosta.site
Port 22
Target Path /home/$USER/web/$DOMAIN/public_html

FileZilla Quick Setup:

  1. Open FileZilla → enter Host: sftp://hosta.site (or server IP).
  2. Enter your Hosta account username and password, with Port: 22.
  3. Click Quickconnect. When prompted for unknown host key, verify and accept.
  4. In the Remote site pane (right), browse to /home/<user>/web/<domain>/public_html.
  5. Drag and drop your local files from the left pane into public_html.

Automated Upload-On-Save in Visual Studio Code:

Install the SFTP extension by Natizyskunk in VS Code and create .vscode/sftp.json:

{
  "name": "Hosta-Production",
  "host": "hosta.site",
  "protocol": "sftp",
  "port": 22,
  "username": "your_username",
  "remotePath": "/home/your_username/web/yourdomain.com/public_html",
  "uploadOnSave": true,
  "ignore": [".vscode", ".git", ".DS_Store", "node_modules"]
}
Method C: Git Deployment & Terminal CLI (Fastest for Developers)

If you have SSH shell access enabled on your account, terminal tools provide instantaneous, automated deployment:

1. Direct Git Clone & Pull Workflow 

# 1. Connect via SSH to your Hosta container
ssh your_username@hosta.site

# 2. Enter your web root
cd /home/your_username/web/yourdomain.com/public_html

# 3. Clone your GitHub / GitLab repository directly into the current directory
git clone https://github.com/username/project.git .

# 4. Pull future updates at any time:
git pull origin main

2. Syncing Local Changes via rsync (Excludes heavy node_modules) 

# Run from your local project directory on your laptop:
rsync -avz --progress --exclude 'node_modules' --exclude '.git' ./ your_username@hosta.site:/home/your_username/web/yourdomain.com/public_html/

3. Copying Production Build Bundles via scp 

# Copy production Vite / React dist bundle to server:
scp -r ./dist/* your_username@hosta.site:/home/your_username/web/yourdomain.com/public_html/
STEP 3

Configuring & Starting Your Technology Stack

Select Your Framework Below
Stack A: Static HTML/CSS/JS Sites & SPAs (React, Vue, Vite, Vanilla)

Static websites require zero backend process configuration. Nginx serves HTML, CSS, JavaScript bundles, images, and fonts with automated compression and caching.

1. Verify Entrance File Location:

Ensure your primary entry point (index.html) is placed directly inside /home/$USER/web/$DOMAIN/public_html/, and not inside a subfolder.

2. Modern Build Output (Vite / React / Vue):

Run npm run build locally. Then upload the compiled contents of the dist/ or build/ folder into public_html.

3. Client-Side SPA Routing Note:

If you use React Router or Vue Router in HTML5 History mode (/dashboard, /profile), refreshing the browser requires Nginx to fallback to index.html. Hosta's standard web templates support Single Page Apps automatically.

PRO TIP: Clearing Browser & Edge Cache

If newly uploaded assets don't appear immediately, perform a hard refresh in your browser with Ctrl + F5 (Windows) or Cmd + Shift + R (Mac) to bypass local cache.

Stack B: Node.js & Dynamic Web Apps (Express, Nest, Fastify, Next.js Standalone)

Node.js applications execute as ongoing background processes managed by PM2. Nginx acts as a high-performance reverse proxy routing incoming HTTPS traffic on port 443 to your application's local port (e.g. http://127.0.0.1:3000).

1. Install Dependencies on Server: 
cd /home/your_username/web/yourdomain.com/public_html
npm install --production
2. Production Environment (.env) Setup: 
PORT=3000
NODE_ENV=production
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=your_username_dbname
DB_USER=your_username_dbuser
DB_PASSWORD=your_secure_password
3. Manage Processes with PM2 (Process Manager): 
# Start your app under PM2 process supervisor
pm2 start server.js --name "my-app" --time

# Verify running status, CPU, and RAM
pm2 status

# Live streaming logs
pm2 logs my-app

# Restart app after uploading updated code
pm2 restart my-app

# Ensure application automatically restarts after server reboot
pm2 save
pm2 startup
PRO TIP: Port Binding in server.js

In your Express code, always listen to process.env.PORT || 3000:
const PORT = process.env.PORT || 3000; app.listen(PORT, '0.0.0.0', () => console.log(`Server on ${PORT}`));

Stack C: PHP & Laravel Web Applications (PHP-FPM + Composer + Artisan)

Laravel uses PHP-FPM managed through the Hosta Control Panel. Follow these 5 explicit steps to ensure your application starts cleanly, securely, and without 500 server errors.

STEP 3.1 Set Web Root to public_html/public (Mandatory Security Step)

In Laravel, your front controller (index.php) lives inside the public/ directory. Setting this custom document root prevents visitors from directly accessing your sensitive .env database credentials and source code:

  1. In the Hosta Dashboard, navigate to Web Domains.
  2. Click Edit Domain (pencil icon) next to your domain.
  3. Expand the Advanced Options accordion.
  4. Check Custom Document Root and set the path to: /home/<user>/web/<domain>/public_html/public
  5. Click Save to reload Nginx configuration.
STEP 3.2 Install Composer Dependencies on Server:

Run inside your application directory to download production packages without heavy development test suites: 

cd /home/your_username/web/yourdomain.com/public_html
composer install --no-dev --optimize-autoloader
STEP 3.3 Configure .env & Generate Application Encryption Key:

Laravel requires an AES-256 encryption key. If APP_KEY is missing, every page will crash with a 500 error: 

# 1. Create production environment file
cp .env.example .env

# 2. Generate unique cryptographic application key
php artisan key:generate
STEP 3.4 Set 775 Permissions on Storage & Bootstrap Cache:

The PHP-FPM web engine needs permission to write session states, rendered Blade views, and log files: 

# Grant web worker write access
chmod -R 775 storage bootstrap/cache
chown -R $USER:$USER storage bootstrap/cache
STEP 3.5 Run Migrations & Build Production Cache:

Apply database schema migrations and compile routes/views for 10x faster response times: 

# 1. Run database schema migrations
php artisan migrate --force

# 2. Create public storage symlink for uploaded files
php artisan storage:link

# 3. Cache routes, configuration, and views
php artisan config:cache
php artisan route:cache
php artisan view:cache
PRO TIP: Refreshing Cached Configuration

Whenever you edit database credentials or keys in your .env on the server, you must refresh the config cache by running:
php artisan config:clear && php artisan config:cache. Otherwise, Laravel continues executing old cached settings!

Verification, Runtime Logs & Troubleshooting

Inspecting Server Errors & Live Status
SSL & HTTPS Verification

Open https://yourdomain.com in your browser. Look for the secure padlock icon. Let's Encrypt certificates are provisioned automatically via HestiaCP and renewed every 60 days via system cron.

Cloudflare CDN & DDoS Shield

For *.hosta.site subdomains, Cloudflare edge proxying handles HTTP/2, HTTP/3, and DDoS mitigation automatically before traffic reaches port 443 on our server.

Where to Inspect Server Runtime Logs

Component Log File Path Live Streaming Command
Nginx Web Server /home/$USER/web/$DOMAIN/logs/$DOMAIN.error.log tail -n 50 -f .../$DOMAIN.error.log
PHP / Laravel public_html/storage/logs/laravel.log tail -n 50 -f storage/logs/laravel.log
Node.js (PM2) ~/.pm2/logs/my-app-error.log pm2 logs my-app --lines 50

Common Errors & Step-by-Step Fix Recipes

502 Bad Gateway Node.js / PM2
Beginner Analogy: Nginx (the front door receptionist) answered the visitor, but the backend application in the kitchen (your Node.js process) didn't answer the internal phone at 127.0.0.1:3000 because it crashed, stopped, or is listening on the wrong port.
Probable Causes:
  • Node.js app has not been started with PM2 or crashed on startup.
  • App is listening on wrong port (must listen on process.env.PORT || 3000).
  • Missing environment variables in .env causing fatal exception.
Terminal Fix Sequence: 
# 1. Check if process is online or errored
pm2 status

# 2. View runtime crash stack traces
pm2 logs --lines 50

# 3. Test starting manually to see startup errors
node server.js

# 4. Restart process once resolved
pm2 restart all
500 Internal Server Error PHP / Laravel
Beginner Analogy: Nginx successfully reached your PHP backend, but the PHP script encountered a fatal syntax exception, missing secret key, or write permission refusal before sending any HTML.
Probable Causes:
  • Missing Laravel encryption key (APP_KEY empty in .env).
  • PHP-FPM web worker cannot write to storage/ or bootstrap/cache/.
  • Incorrect database username, database name, or password in .env.
Terminal Fix Sequence: 
# 1. View the exact Laravel error trace
tail -n 50 public_html/storage/logs/laravel.log

# 2. Generate missing application encryption key
php artisan key:generate

# 3. Fix folder write permissions (mode 775)
chmod -R 775 storage bootstrap/cache

# 4. Clear old configuration cache
php artisan config:clear && php artisan cache:clear
404 Not Found Web Root Path

Cause: Nginx looked for index.html inside public_html but found nothing. Most often happens when extracting a ZIP containing a root folder (e.g. public_html/my-app/index.html), or when Laravel Document Root is not pointed to public_html/public.

Terminal Fix: 
# Move nested files up one level to web root:
mv public_html/nested-folder/* public_html/
rmdir public_html/nested-folder
Error: Cannot find module 'express' Node.js NPM

Cause: Dependencies were excluded during upload or Git clone (which is standard practice), but npm install was not yet executed on the server container.

Terminal Fix: 
cd /home/$USER/web/yourdomain.com/public_html
npm install --production
pm2 restart all

Connecting Custom Domains & DNS Setup

Point your own domain from Namecheap, GoDaddy, or Cloudflare to your Hosta container.

Whether you are using a free *.hosta.site subdomain or pointing an apex domain like myproject.com, DNS records translate your domain into our server's IP address.

Required DNS Records for External Registrars TTL: Automatic / 300s
Type Host / Name Target / Value / IP Proxy / Status Purpose
A @ (root) 142.91.97.73 DNS Only / Proxied Points root apex domain to Hosta server
A www 142.91.97.73 DNS Only / Proxied Routes www.yourdomain.com requests
CNAME subdomain hosta.site CNAME Alias Optional alias mapping for subdomains

Cloudflare Edge Proxy & SSL Handshake

When using our default free subdomains (*.hosta.site), traffic routes through Cloudflare's global edge network before reaching our server cluster on port 8083 / 443. This gives your applications immediate DDoS protection, HTTP/3 protocol support, and automatic wildcard SSL.

Verifying DNS Propagation (Terminal Commands)

Run these commands in your local command prompt or terminal to confirm your DNS records have fully propagated: 

dig +short A yourdomain.com @1.1.1.1
nslookup yourdomain.com 8.8.8.8

Note on DNS Propagation: External domain updates at registrars like GoDaddy or Namecheap can take anywhere from 5 minutes to 24 hours to spread worldwide. Do not request Let's Encrypt certificates until the A record resolves to our IP address.

Email Architecture: Inbound Forwarding & Transactional SMTP

Cloud-Native Setup

To deliver maximum web performance and protect IP deliverability against spam blacklisting, Hosta does not operate local mailbox daemons (POP3/IMAP). Instead, we recommend modern, zero-maintenance cloud email architectures:

Inbound Forwarding: Cloudflare Email Routing

Receive professional email at your custom domain (e.g. contact@yourdomain.com) at zero cost. Cloudflare forwards incoming emails straight to your personal Gmail, Outlook, or iCloud address without using any server disk quota.

Setup: Cloudflare Dashboard → Email → Email Routing → Enable
Outbound System Mail: Brevo / SMTP Relay

For user registration, password resets, and contact forms in Node.js or Laravel, use Brevo (free 300 emails/day), Resend, or SendGrid via standard SMTP relay on Port 587 (TLS). 

MAIL_MAILER=smtp
MAIL_HOST=smtp-relay.brevo.com
MAIL_PORT=587
MAIL_ENCRYPTION=tls
MAIL_USERNAME=your_brevo_login
MAIL_PASSWORD=your_smtp_key

Developer REST API Reference

Automate domain provisioning, databases, and quota monitoring via programmatic HTTPS requests.

Base Endpoint: https://hosta.site/api/hosting JSON Payload & Responses
Method Endpoint Path Description Auth Required
POST /api/hosting/domains Provisions a new web domain + triggers Let's Encrypt SSL Bearer Token
GET /api/hosting/domains Lists all active web domains for user Bearer Token
POST /api/hosting/databases Creates a new MySQL database + database user Bearer Token
GET /api/hosting/databases Fetches database list and connection credentials Bearer Token
GET /api/hosting/stats Returns disk, bandwidth, and database metrics Bearer Token
Example: Create a New Web Domain 
curl -X POST https://hosta.site/api/hosting/domains \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN" \
  -d '{
    "domain": "myproject.hosta.site",
    "enableSsl": true
  }'
const axios = require('axios');

async function provisionDomain() {
  try {
    const response = await axios.post('https://hosta.site/api/hosting/domains', {
      domain: 'myproject.hosta.site',
      enableSsl: true
    }, {
      headers: {
        'Authorization': 'Bearer YOUR_SESSION_TOKEN',
        'Content-Type': 'application/json'
      }
    });

    console.log('Domain Provisioned:', response.data);
  } catch (error) {
    console.error('Error:', error.response?.data || error.message);
  }
}

provisionDomain();
const response = await fetch('https://hosta.site/api/hosting/domains', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer YOUR_SESSION_TOKEN'
  },
  body: JSON.stringify({
    domain: 'myproject.hosta.site',
    enableSsl: true
  })
});

const result = await response.json();
console.log(result);
import requests

url = "https://hosta.site/api/hosting/domains"
headers = {
    "Authorization": "Bearer YOUR_SESSION_TOKEN",
    "Content-Type": "application/json"
}
payload = {
    "domain": "myproject.hosta.site",
    "enableSsl": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
